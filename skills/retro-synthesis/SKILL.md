# Retro Synthesis

**Who it's for:** a PMO that runs retros but rarely connects lessons across projects, so the same problems repeat.
**What it gives back:** the 3–5 patterns behind most slips, and fixes that change the process, not just one project.

## Inputs
- Retro notes, boards, or transcripts from one or more projects
- Optional: each project's planned versus actual dates and its final status

## Steps
1. **Pull every "what went wrong" and "what went well"** item, keeping the project name next to each.
2. **Group by root cause type:** unclear scope, late decision, dependency on another team, capacity, handoff gap, tool or data problem, or communication.
3. **Rank by how often each appears across projects**, not by how loud it was in a single retro.
4. **For the top 3–5 patterns,** propose **one process fix** each (a change to intake, templates, gates, or cadence) with a suggested owner.
5. **Keep a "what to repeat" list.** Wins are patterns too.
6. **Stop for PgM review** before it's shared.

## Output template
```
RETRO SYNTHESIS: <scope>, <n> projects
Top patterns
| Pattern | Projects affected | Example | Proposed process fix | Owner |
Worth repeating
Open questions for the next planning cycle
```

## Guardrails
- No blame. Write about the process, never about individuals.
- Cite which projects each pattern came from.
